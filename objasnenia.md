# Объяснения по коду лабораторной работы

## 1. typedef struct - что это?

**Структура** - это способ объединить несколько переменных в одну "коробку".

### Пример без typedef:
```c
struct Person {
    char* name;
    int age;
};

// Использование:
struct Person p1;  // Приходится писать "struct" каждый раз
```

### С typedef:
```c
typedef struct {
    char* name;
    int age;
} Person;

// Использование:
Person p1;  // Пишем просто "Person", без "struct"
```

**`typedef`** - это просто **псевдоним**, чтобы не писать слово `struct` постоянно.

**Структура Person:**
- `char* name` - указатель на строку (имя человека)
- `int age` - возраст

---

## 2. Указатель на функцию: `int (*compare)(const void*, const void*)`

Это **указатель на функцию**.

### Разбор по частям:

```c
int (*compare)(const void*, const void*)
```

- **`int`** - функция возвращает int (целое число)
- **`(*compare)`** - это УКАЗАТЕЛЬ на функцию с именем `compare`
- **`(const void*, const void*)`** - функция принимает два параметра типа `const void*`

### Зачем это нужно?

Представь: у тебя есть универсальная сортировка. Она не знает, что сортирует - числа? людей? строки?

**Решение:** Ты передаешь ей ФУНКЦИЮ, которая умеет сравнивать твои данные.

### Пример:

```c
// Функция сравнения для int
int compare_int(const void* a, const void* b) {
    int x = *(int*)a;
    int y = *(int*)b;
    if (x < y) return -1;   // a меньше b
    if (x > y) return 1;    // a больше b
    return 0;               // равны
}

// Теперь можешь передать эту функцию в сортировку:
universal_merge_sort(array, count, sizeof(int), compare_int);
//                                                 ^^^^^^^^^
//                                          передаем функцию!
```

## 3. void* - универсальный указатель

**`void*`** - это "универсальный указатель". Он может указывать на ЧТО УГОДНО:
- на int
- на char
- на структуру Person
- на что угодно!

Поэтому наша сортировка и называется **универсальной** - она работает с `void*` и не знает, что именно сортирует.

---

## 4. const void* - константный указатель

**`const`** означает, что данные **только для чтения**, их нельзя изменить внутри функции.

```c
int compare_int(const void* a, const void* b) {
    // Мы ЧИТАЕМ a и b, но не меняем их
}
```

## 5. Функции сравнения

### compare_int - сравнение целых чисел

```c
int compare_int(const void* a, const void* b) {
    int int_a = *(const int*)a;  // Превращаем void* в int* и берем значение
    int int_b = *(const int*)b;

    if (int_a < int_b) return -1;  // a меньше b
    if (int_a > int_b) return 1;   // a больше b
    return 0;                      // равны
}
```

**Что происходит:**
- `(const int*)a` - приводим `void*` к типу `int*`
- `*(const int*)a` - берем значение по этому указателю
- Возвращаем: `-1`, `1` или `0` в зависимости от сравнения

### compare_person - сравнение структур Person

```c
int compare_person(const void* a, const void* b) {
    const Person* p1 = (const Person*)a;  // Превращаем void* в Person*
    const Person* p2 = (const Person*)b;

    // Сначала сравниваем имена
    int name_cmp = strcmp(p1->name, p2->name);
    if (name_cmp != 0) return name_cmp;

    // Если имена одинаковые, сравниваем возраст
    if (p1->age < p2->age) return -1;
    if (p1->age > p2->age) return 1;
    return 0;
}
```

**Логика:**
1. Сначала сравниваем по имени (strcmp)
2. Если имена одинаковые, сравниваем по возрасту
3. Это называется "лексикографическая сортировка"

## 6. Освобождение памяти

```c
void free_person_array(Person* array, int count) {
    if (array == NULL) return;

    for (int i = 0; i < count; i++) {
        free(array[i].name);  // Освобождаем память для каждого имени
    }
    free(array);  // Освобождаем сам массив
}
```

**ВАЖНО:** В C нужно вручную освобождать память!
- Сначала освобождаем память для каждого `name` (строки выделялись отдельно)
- Потом освобождаем сам массив структур

## Итого простыми словами:

1. **`typedef struct`** - создаем свой тип данных (например, Person)
2. **`int (*compare)(...)`** - указатель на функцию, которая сравнивает два элемента
3. **`void*`** - универсальный указатель "на что угодно"
4. **`const`** - "только для чтения"
5. **Функции сравнения** возвращают: `-1` (меньше), `0` (равно), `1` (больше)
6. **Всегда освобождай память** - `free()` для всего, что выделял через `malloc()`

## 7. Алгоритм сортировки слиянием (Merge Sort)

**Сортировка слиянием** - это алгоритм "разделяй и властвуй".

### Принцип работы:

1. **РАЗДЕЛЯЙ:** Делим массив пополам
2. **СОРТИРУЙ:** Рекурсивно сортируем каждую половину
3. **ОБЪЕДИНЯЙ:** Сливаем две отсортированные половины в одну

### Пример на числах:

```
Исходный массив: [5, 2, 8, 1]

Шаг 1 - РАЗДЕЛЯЕМ:
[5, 2, 8, 1]
   ↓
[5, 2]  [8, 1]

Шаг 2 - РАЗДЕЛЯЕМ ЕЩЕ:
[5]  [2]    [8]  [1]

Шаг 3 - СЛИВАЕМ:
[5]  [2] → [2, 5]
[8]  [1] → [1, 8]

Шаг 4 - СЛИВАЕМ ФИНАЛЬНО:
[2, 5]  [1, 8] → [1, 2, 5, 8]
```

### Сложность алгоритма:

- **Время:** O(n log n) - очень быстро!
- **Память:** O(n) - нужна дополнительная память для временных массивов

## 8. Как работает функция merge() - слияние

Функция `merge()` берет два отсортированных массива и объединяет их в один отсортированный.

### Алгоритм слияния:

```c
// У нас есть два отсортированных массива:
L = [2, 5]
R = [1, 8]

// Результат - пустой массив:
result = []

// Сравниваем первые элементы:
2 vs 1 → 1 меньше, берем его
result = [1]

// Сравниваем 2 vs 8 → 2 меньше
result = [1, 2]

// Сравниваем 5 vs 8 → 5 меньше
result = [1, 2, 5]

// В R остался только 8, добавляем его
result = [1, 2, 5, 8]
```

### Код функции merge() построчно:

```c
static void merge(void* array, int left, int mid, int right, ...) {
    int n1 = mid - left + 1;  // Размер левой части
    int n2 = right - mid;     // Размер правой части

    // Выделяем временные массивы
    char* L = (char*)malloc(n1 * element_size);
    char* R = (char*)malloc(n2 * element_size);

    // Копируем данные во временные массивы
    for (int i = 0; i < n1; i++)
        memcpy(L + i * element_size, ...);  // Копируем левую часть
    for (int j = 0; j < n2; j++)
        memcpy(R + j * element_size, ...);  // Копируем правую часть

    // ГЛАВНЫЙ ЦИКЛ - сливаем массивы
    int i = 0, j = 0, k = left;
    while (i < n1 && j < n2) {
        if (compare(L[i], R[j]) <= 0) {
            array[k] = L[i];  // Берем из левого
            i++;
        } else {
            array[k] = R[j];  // Берем из правого
            j++;
        }
        k++;
    }

    // Копируем оставшиеся элементы
    while (i < n1) { array[k++] = L[i++]; }
    while (j < n2) { array[k++] = R[j++]; }

    free(L);
    free(R);
}
```

## 9. Почему используется memcpy()?

**`memcpy()`** - это функция копирования памяти **побайтово**.

### Зачем она нужна?

Мы работаем с `void*` - универсальным указателем. Мы НЕ ЗНАЕМ тип данных!
- Это int? (4 байта)
- Это Person? (может быть 16 байт)
- Это что-то еще?

**Решение:** Копируем память побайтово!

```c
memcpy(destination, source, num_bytes);
       ↑            ↑        ↑
    куда копируем  откуда   сколько байт
```

### Пример:

```c
// Копирование одного элемента размером element_size
memcpy(L + i * element_size,           // Куда: L[i]
       arr + (left + i) * element_size, // Откуда: arr[left + i]
       element_size);                   // Сколько: размер одного элемента
```

**Что происходит:**
- `L + i * element_size` - адрес i-го элемента в массиве L
- Копируем `element_size` байт (целый элемент)
- Работает для ЛЮБОГО типа данных!

## 10. Рекурсия в merge_sort()

**Рекурсия** - это когда функция вызывает САМА СЕБЯ.

### Код:

```c
static void merge_sort(void* array, int left, int right, ...) {
    if (left < right) {                    // Базовый случай: массив > 1 элемента
        int mid = left + (right - left) / 2;  // Находим середину

        merge_sort(array, left, mid, ...);    // Сортируем ЛЕВУЮ половину (РЕКУРСИЯ!)
        merge_sort(array, mid + 1, right, ...); // Сортируем ПРАВУЮ половину (РЕКУРСИЯ!)

        merge(array, left, mid, right, ...);  // Сливаем обе половины
    }
}
```

### Как это работает:

```
Вызов 1: merge_sort([5, 2, 8, 1], 0, 3)
  ↓
  mid = 1
  ↓
  Вызов 2: merge_sort([5, 2], 0, 1)    ← РЕКУРСИЯ!
    ↓
    mid = 0
    ↓
    Вызов 3: merge_sort([5], 0, 0)    ← left == right, выходим
    Вызов 4: merge_sort([2], 1, 1)    ← left == right, выходим
    ↓
    merge([5, 2])  → [2, 5]           ← Сливаем!
  ↓
  Вызов 5: merge_sort([8, 1], 2, 3)    ← РЕКУРСИЯ!
    ... аналогично ...
  ↓
  merge([2, 5], [1, 8])  → [1, 2, 5, 8]  ← Финальное слияние!
```

## 12. Что такое граф?

**Граф** - это набор вершин (точек) и ребер (линий между точками).

### Пример графа:

```
    (0)---6---(1)
     |         |
     7         5
     |         |
    (3)---8---(2)
```

**Вершины:** 0, 1, 2, 3
**Ребра:** 0→1 (вес 6), 0→3 (вес 7), 1→2 (вес 5), 2→3 (вес 8)

### Матрица смежности:

Это таблица, где строка i и столбец j содержат вес ребра от вершины i к вершине j.

```
     0   1   2   3
0 [  0   6   0   7 ]
1 [  0   0   5   0 ]
2 [  0   0   0   8 ]
3 [  0   0   0   0 ]
```

- `graph[0][1] = 6` → есть ребро 0→1 с весом 6
- `graph[0][2] = 0` → НЕТ ребра 0→2

**Задача:** Найти кратчайшие пути от одной вершины (стартовой) до всех остальных.

### Пример:

```
Граф:
(0)---2-->(1)
 |         |
 4         1
 ↓         ↓
(2)<--3---(3)

Кратчайшие пути от вершины 0:
- до 0: 0 (сам до себя)
- до 1: 2 (путь: 0→1)
- до 2: 4 (путь: 0→2)
- до 3: 3 (путь: 0→1→3)
```

## 14. Алгоритм Беллмана-Форда - пошагово

**Беллман-Форд** находит кратчайшие пути даже в графах с **отрицательными весами** ребер.

### Алгоритм из 3 шагов:

**ШАГ 1: Инициализация**
```c
for (int i = 0; i < vertices; i++)
    distances[i] = INF;  // Все вершины недостижимы
distances[start_vertex] = 0;  // Стартовая вершина - расстояние 0
```

**ШАГ 2: Релаксация (повторяем V-1 раз)**
```c
for (int i = 0; i < vertices - 1; i++) {
    for (каждое ребро u → v с весом w) {
        if (distances[u] + w < distances[v]) {
            distances[v] = distances[u] + w;  // РЕЛАКСАЦИЯ!
        }
    }
}
```

**ШАГ 3: Проверка отрицательного цикла**
```c
for (каждое ребро u → v с весом w) {
    if (distances[u] + w < distances[v]) {
        return "Есть отрицательный цикл!";
    }
}
```

## 15. Что такое релаксация?

**Релаксация** - это попытка улучшить текущее расстояние до вершины.

### Пример:

```
Текущие расстояния:
distances[0] = 0
distances[1] = 10
distances[2] = INF

Ребро: 1 → 2 с весом 5

ПРОВЕРЯЕМ:
distances[1] + 5 < distances[2] ?
10 + 5 < INF ?
15 < INF ? ДА!

РЕЛАКСИРУЕМ:
distances[2] = 15  ← Обновили!
```

**Релаксация** = "Попробовали новый путь, он оказался короче!"

## 16. Пример работы алгоритма

### Граф:

```
    (0)---6-->(1)
     |         |
     7         5
     ↓         ↓
    (3)<--8---(2)
```

Матрица:
```
     0   1   2   3
0 [  0   6   0   7 ]
1 [  0   0   5   0 ]
2 [  0   0   0   8 ]
3 [  0   0   0   0 ]
```

### Выполнение:

**Инициализация:**
```
distances = [0, INF, INF, INF]
```

**Итерация 1:**
- Ребро 0→1 (вес 6): distances[1] = 0 + 6 = 6
- Ребро 0→3 (вес 7): distances[3] = 0 + 7 = 7

```
distances = [0, 6, INF, 7]
```

**Итерация 2:**
- Ребро 1→2 (вес 5): distances[2] = 6 + 5 = 11

```
distances = [0, 6, 11, 7]
```

**Итерация 3:**
- Ребро 2→3 (вес 8): distances[3] = 11 + 8 = 19 (но 7 < 19, не обновляем)

```
distances = [0, 6, 11, 7]  ← Финальный результат!
```

## 17. Отрицательные циклы

**Отрицательный цикл** - это цикл, суммарный вес которого отрицателен.

### Пример:

```
(0)---2-->(1)
 ↑         |
 |        -5
-3         ↓
 |        (2)
 └---------┘
```

Цикл: 0 → 1 → 2 → 0
Вес цикла: 2 + (-5) + (-3) = **-6** (отрицательный!)

**Проблема:** Можно ходить по этому циклу бесконечно, уменьшая расстояние до -∞.

### Как обнаружить?

После (V-1) итераций пытаемся еще раз релаксировать ребра.
- Если хоть одно ребро можно релаксировать → **есть отрицательный цикл!**

```c
// После V-1 итераций проверяем:
for (каждое ребро u → v с весом w) {
    if (distances[u] + w < distances[v]) {
        return 1;  // Отрицательный цикл найден!
    }
}
```

---

## 18. Сложность алгоритма

- **Время:** O(V × E) где V - вершины, E - ребра
  - Внешний цикл: V-1 итерация
  - Внутренний: проверяем все E ребер
  - Итого: O(V × E)

- **Память:** O(V) для массива distances

### Сравнение с другими алгоритмами:

| Алгоритм | Время | Отрицательные веса? |
|----------|-------|---------------------|
| Беллман-Форд | O(V × E) | ✅ ДА |
| Дейкстра | O(V²) или O(E log V) | ❌ НЕТ |

## 19. Матрица смежности vs Список смежности

### Матрица смежности (наш случай):

```c
int** graph = (int**)malloc(vertices * sizeof(int*));
for (int i = 0; i < vertices; i++)
    graph[i] = (int*)malloc(vertices * sizeof(int));

// Доступ: graph[i][j] - вес ребра i→j
```

**Плюсы:**
- Быстрый доступ к любому ребру: O(1)
- Легко проверить, есть ли ребро

**Минусы:**
- Память: O(V²) - даже если ребер мало
- Перебор всех ребер: O(V²)

### Список смежности (альтернатива):

```c
struct Edge { int to, weight; };
struct Edge* graph[vertices];  // Для каждой вершины - список ребер
```

**Плюсы:**
- Память: O(V + E) - только для существующих ребер
- Перебор ребер: O(E)

## 20. Работа с двумерными массивами

### Выделение памяти для матрицы:

```c
// Выделяем массив указателей (строки)
int** graph = (int**)malloc(vertices * sizeof(int*));

// Для каждой строки выделяем массив (столбцы)
for (int i = 0; i < vertices; i++) {
    graph[i] = (int*)malloc(vertices * sizeof(int));
}

// Теперь можно использовать: graph[i][j]
```

**Что происходит:**
```
graph → [указатель на строку 0] → [0, 6, 0, 7]
        [указатель на строку 1] → [0, 0, 5, 0]
        [указатель на строку 2] → [0, 0, 0, 8]
        [указатель на строку 3] → [0, 0, 0, 0]
```

### Освобождение памяти:

```c
void free_graph(int** graph, int vertices) {
    // Сначала освобождаем каждую строку
    for (int i = 0; i < vertices; i++) {
        free(graph[i]);
    }
    // Потом освобождаем массив указателей
    free(graph);
}
```

**ВАЖНО:** Освобождаем в обратном порядке!

## 21. INF - бесконечность

```c
#define INF INT_MAX  // Максимальное значение int
```

**Зачем нужно?**
- Обозначает "недостижимую" вершину
- `distances[v] = INF` → до вершины v еще нет пути

**Почему INT_MAX?**
- Это максимальное значение типа int (обычно 2,147,483,647)
- Любое реальное расстояние будет меньше

### Осторожно с переполнением!

```c
// ПРОБЛЕМА:
if (distances[u] + weight < distances[v])  // Если distances[u] = INF, переполнение!

// РЕШЕНИЕ:
if (distances[u] == INF) continue;  // Проверяем перед сложением
long long new_dist = (long long)distances[u] + weight;  // Используем long long
```

## Итого по алгоритму Беллмана-Форда:

1. **Граф** - вершины + ребра с весами
2. **Матрица смежности** - таблица весов ребер
3. **Алгоритм Беллмана-Форда** - находит кратчайшие пути
4. **Релаксация** - улучшение текущего расстояния
5. **Отрицательный цикл** - цикл с отрицательным суммарным весом
6. **Сложность O(V × E)** - медленнее Дейкстры, но работает с отрицательными весами
7. **INF = INT_MAX** - обозначение недостижимости
8. **Двумерные массивы** - массив указателей на массивы

## 22. Почему используется char* для работы с void*?

**Вопрос:** В функции merge() мы преобразуем `void*` в `char*`. Почему именно char?

**Ответ:** `char` в C всегда занимает **ровно 1 байт**!

```c
void* array;  // Универсальный указатель - не знаем размер элемента
char* arr = (char*)array;  // Теперь работаем с байтами
```

**Почему это важно:**
- Когда прибавляем к указателю число, C сдвигает адрес на `число × размер_типа`
- `int* p; p + 1` → сдвиг на 4 байта (размер int)
- `char* p; p + 1` → сдвиг на 1 байт
- Поэтому `arr + 5 * element_size` = точный адрес 5-го элемента!

**Пример:**
```c
int array[3] = {10, 20, 30};
void* ptr = array;

// Хотим получить 2-й элемент (индекс 1)
char* byte_ptr = (char*)ptr;
int* result = (int*)(byte_ptr + 1 * sizeof(int));  // Сдвиг на 4 байта
// *result = 20
```

## 23. Зачем нужен element_size?

**Вопрос:** Почему мы постоянно передаем `element_size` и умножаем на него?

**Ответ:** Универсальная функция НЕ ЗНАЕТ, какой размер у элементов!

```c
// Для int:
universal_merge_sort(array, count, sizeof(int), compare_int);
//                                  ^^^^^^^^^^^
//                                  4 байта

// Для Person:
universal_merge_sort(array, count, sizeof(Person), compare_person);
//                                  ^^^^^^^^^^^^^^
//                                  16 байт (зависит от структуры)
```

**Почему это нужно:**
- `memcpy(dest, src, element_size)` - копирует РОВНО столько байт, сколько занимает элемент
- `L + i * element_size` - вычисляет адрес i-го элемента

**Без element_size** функция не знала бы, сколько памяти копировать!

## 24. Что такое static перед функцией?

**Вопрос:** Почему `merge()` и `merge_sort()` объявлены как `static`?

**Ответ:** `static` означает, что функция **видна только внутри этого файла**!

```c
// В sorting.c:
static void merge(...) { ... }  // Видна только в sorting.c

void universal_merge_sort(...) { ... }  // Видна везде (публичная)
```

**Зачем это нужно:**
- **Инкапсуляция** - скрываем внутренние детали реализации
- **Избегаем конфликтов имен** - в другом файле может быть своя функция merge()
- **Безопасность** - пользователь не может случайно вызвать внутреннюю функцию

**Аналогия:**
- `static` = приватная функция (как в Python `_function()`)
- Обычная функция = публичная (доступна всем)

## 25. Почему используется long long в Беллмане-Форде?

**Вопрос:** Зачем `long long new_dist` если distances имеет тип int?

```c
long long new_dist = (long long)distances[u] + graph[u][v];
```

**Ответ:** Чтобы **избежать переполнения при сложении**!

**Проблема:**
```c
int a = 2000000000;  // Близко к INT_MAX (2147483647)
int b = 200000000;
int sum = a + b;  // ПЕРЕПОЛНЕНИЕ! Результат отрицательный!
```

**Решение:**
```c
int a = 2000000000;
int b = 200000000;
long long sum = (long long)a + b;  // Нет переполнения!
// sum = 2200000000 (правильно)
```

**В алгоритме:**
- Если `distances[u] = 2000000000` и `graph[u][v] = 200000000`
- Без long long: переполнение → неправильный результат
- С long long: корректное вычисление → потом проверяем и сохраняем в int

## 26. Почему проверяем distances[u] == INF?

**Вопрос:** Зачем проверка `if (distances[u] == INF) continue;`?

```c
for (int u = 0; u < vertices; u++) {
    if (distances[u] == INF) continue;  // Зачем?
    ...
}
```

**Ответ:** Нельзя складывать INF с числами!

**Проблема:**
```c
#define INF INT_MAX  // 2147483647

int dist = INF;
int weight = 10;
int sum = dist + weight;  // ПЕРЕПОЛНЕНИЕ! sum становится отрицательным!
```

**Решение:**
- Если вершина недостижима (distance = INF), пропускаем её
- Не пытаемся вычислять `INF + что-то`

**Логика:**
- Если до u нельзя дойти, то и через u нельзя дойти до других вершин
- Поэтому просто пропускаем такие вершины

## 27. Зачем нужны проверки malloc() == NULL?

**Вопрос:** Зачем проверять `if (ptr == NULL)` после malloc?

```c
char* L = (char*)malloc(n1 * element_size);
if (L == NULL) {  // Зачем?
    return;
}
```

**Ответ:** malloc() может **НЕ СУМЕТЬ** выделить память!

**Когда malloc() возвращает NULL:**
1. Закончилась свободная память (RAM)
2. Запросили слишком большой блок
3. Фрагментация памяти

**Что будет БЕЗ проверки:**
```c
char* L = (char*)malloc(1000000000000);  // Просим 1 TB
// L = NULL (недостаточно памяти)
L[0] = 5;  // SEGMENTATION FAULT! Программа упадет!
```

**С проверкой:**
```c
char* L = (char*)malloc(1000000000000);
if (L == NULL) {
    printf("Oshibka vydeleniya pamyati\n");
    return;  // Корректно выходим
}
L[0] = 5;  // Безопасно - знаем, что память выделена
```

**Правило:** ВСЕГДА проверяй результат malloc/realloc!

## 28. Почему realloc требует временную переменную?

**Вопрос:** Почему мы не делаем просто `arr = realloc(arr, new_size)`?

```c
// ПЛОХО:
*int_array = (int*)realloc(*int_array, new_size);

// ХОРОШО:
int* temp = (int*)realloc(*int_array, new_size);
if (temp == NULL) {
    // Обработка ошибки
}
*int_array = temp;
```

**Ответ:** Если realloc() не сможет выделить память:
- Возвращает NULL
- **Исходный указатель остается ВАЛИДНЫМ!**

**Проблема без temp:**
```c
int* arr = malloc(10 * sizeof(int));
// ... заполнили данными ...

arr = realloc(arr, 1000000000000);  // Просим слишком много
// realloc вернет NULL
// arr теперь NULL
// Исходные данные ПОТЕРЯНЫ НАВСЕГДА!
```

**Правильно с temp:**
```c
int* arr = malloc(10 * sizeof(int));
// ... заполнили данными ...

int* temp = realloc(arr, 1000000000000);
if (temp == NULL) {
    // realloc не смог
    // НО arr все еще указывает на старые данные!
    // Можем продолжить работу или корректно освободить
    free(arr);
    return;
}
arr = temp;  // Успех - обновляем указатель
```

## 29. Что такое "релаксация ребра"?

**Вопрос:** Что означает "релаксировать ребро"?

**Простое объяснение:**

**Релаксация** = попытка улучшить путь

```c
// Текущее расстояние до вершины v
distances[v] = 15

// Нашли новый путь через вершину u с ребром u→v весом 3
new_distance = distances[u] + 3 = 10 + 3 = 13

// РЕЛАКСАЦИЯ:
if (13 < 15) {  // Новый путь короче?
    distances[v] = 13;  // Обновляем!
}
```

**Метафора:**
Представь, что ты натягиваешь резинку между двумя точками. Релаксация - это когда ты нашел более короткий путь и "отпускаешь" резинку, она принимает более короткое положение.

## 30. Почему именно (V-1) итераций в Беллмане-Форде?

**Вопрос:** Почему алгоритм делает именно `vertices - 1` итераций?

**Ответ:** Максимальный простой путь имеет (V-1) ребер!

**Пример с 4 вершинами:**
```
Самый длинный путь БЕЗ ЦИКЛОВ:
0 → 1 → 2 → 3
    ^   ^   ^
    1   2   3 ребра = (4-1) = 3 ребра
```

**Почему этого достаточно:**
- В 1-й итерации находим пути длиной 1 ребро
- Во 2-й итерации находим пути длиной 2 ребра (используя результаты 1-й)
- В 3-й итерации находим пути длиной 3 ребра
- ...
- В (V-1)-й итерации находим все кратчайшие пути

**Если после (V-1) итераций можно еще улучшить путь** → есть отрицательный цикл!

## 31. Как читать синтаксис указателей?

**Вопрос:** Как понять, что означает `int**`, `char*`, `void*`, `int (*func)()`?

**Правило:** Читай **справа налево**!

### Примеры:

```c
int* p;
// p - указатель на int
// Читаем: "p это (*) указатель на int"

int** matrix;
// matrix - указатель на указатель на int
// Читаем: "matrix это (*) указатель на (*) указатель на int"
// = двумерный массив

int (*compare)(const void*, const void*);
// compare - указатель на функцию, возвращающую int
// Читаем: "compare это (*) указатель на функцию,
//          принимающую два const void* и возвращающую int"

const int* p;
// p - указатель на константный int
// Можно менять p, нельзя менять *p

int* const p;
// p - константный указатель на int
// Нельзя менять p, можно менять *p
```

**Трюк для запоминания:** Скобки показывают приоритет!

## 32. Разница между malloc() и calloc()?

**Вопрос:** Чем отличается malloc от calloc?

```c
// malloc - просто выделяет память (может содержать мусор)
int* arr1 = (int*)malloc(10 * sizeof(int));
// arr1[0] = ??? (мусор)

// calloc - выделяет И обнуляет память
int* arr2 = (int*)calloc(10, sizeof(int));
// arr2[0] = 0 (все элементы = 0)
```

**Когда использовать:**
- **malloc** - когда сразу заполнишь данными (быстрее)
- **calloc** - когда нужны нулевые значения по умолчанию

**В нашем коде:** Используем malloc, так как сразу копируем данные через memcpy.
