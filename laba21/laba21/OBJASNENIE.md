# ЧАСТЬ 1: СОРТИРОВКИ

## 🤔 ЧТО ТАКОЕ СОРТИРОВКА?

**Сортировка** - это процесс упорядочивания элементов по определенному правилу (обычно по возрастанию или убыванию).

### Пример из жизни:
Представь, что у тебя есть колода карт, перемешанная в случайном порядке:
```
7♠  2♥  K♦  5♣  A♠  9♥  3♦
```

После сортировки по возрастанию:
```
A♠  2♥  3♦  5♣  7♠  9♥  K♦
```

---

## 🛠️ УНИВЕРСАЛЬНАЯ СОРТИРОВКА В C

### Что значит "универсальная"?

**НЕ универсальная функция** (только для int):
```c
void sort_int(int* array, int count) {
    // Работает только с int
}
```

**Универсальная функция** (работает с ЛЮБЫМ типом):
```c
void universal_sort(void* array, int count, size_t size, int (*compare)(...)) {
    // Работает с int, Person, double, и любым другим типом!
}
```

### Как это работает?

#### 1. **void\* array** - указатель на "что угодно"
```c
void* - это "универсальный" указатель
```
Он может указывать на int, Person, или любой другой тип.

#### 2. **size_t size** - размер одного элемента
```c
sizeof(int) = 4 байта
sizeof(Person) = 16 байт (зависит от структуры)
```

#### 3. **int (\*compare)(...)** - функция сравнения
```c
int compare_int(const void* a, const void* b) {
    int num_a = *(int*)a;  // Преобразуем void* в int*
    int num_b = *(int*)b;

    if (num_a < num_b) return -1;  // a меньше b
    if (num_a > num_b) return 1;   // a больше b
    return 0;                      // a равно b
}
```

## 📊 7 АЛГОРИТМОВ СОРТИРОВКИ

### 🔵 1. MERGE SORT (Сортировка слиянием)

**Идея:** "Разделяй и властвуй"

1. Разделить массив пополам
2. Отсортировать каждую половину (рекурсивно)
3. Слить две отсортированные половины в одну

**Визуализация:**
```
Исходный массив: [5, 2, 8, 1, 9, 3]

Шаг 1: Разделить
    [5, 2, 8]  |  [1, 9, 3]

Шаг 2: Разделить еще
    [5]  [2, 8]  |  [1]  [9, 3]
    [5]  [2] [8]  |  [1]  [9] [3]

Шаг 3: Слить
    [5]  [2, 8]  |  [1]  [3, 9]
    [2, 5, 8]  |  [1, 3, 9]

Шаг 4: Слить все
    [1, 2, 3, 5, 8, 9]
```

**Сложность:** O(n log n) - БЫСТРАЯ
**Память:** O(n) - требует дополнительную память

---

### 🔵 2. BUBBLE SORT (Пузырьковая сортировка)

**Идея:** "Всплытие пузырьков"

Проходим по массиву много раз. На каждом проходе сравниваем соседние элементы и меняем их местами, если они в неправильном порядке.

**Почему "пузырьковая"?** Большие элементы "всплывают" вверх (в конец массива) как пузырьки.

**Визуализация (один проход):**
```
Исходный: [5, 2, 8, 1]

Сравниваем 5 и 2 → меняем: [2, 5, 8, 1]
Сравниваем 5 и 8 → не меняем: [2, 5, 8, 1]
Сравниваем 8 и 1 → меняем: [2, 5, 1, 8]  ← 8 "всплыл" в конец!

После 1 прохода: [2, 5, 1, 8]
После 2 прохода: [2, 1, 5, 8]
После 3 прохода: [1, 2, 5, 8]  ✓ Готово!
```

**Сложность:** O(n²) - МЕДЛЕННАЯ
**Память:** O(1) - не требует дополнительной памяти

---

### 🔵 3. SELECTION SORT (Сортировка выбором)

**Идея:** "Выбирай минимум"

1. Найти минимальный элемент
2. Поставить его на первое место
3. Найти минимум в оставшейся части
4. Повторять до конца

**Визуализация:**
```
Исходный: [5, 2, 8, 1, 9]

Проход 1: Ищем минимум → 1
    Меняем 5 и 1: [1, 2, 8, 5, 9]
                    ↑ закреплено

Проход 2: Ищем минимум в [2, 8, 5, 9] → 2
    Уже на месте: [1, 2, 8, 5, 9]
                       ↑ закреплено

Проход 3: Ищем минимум в [8, 5, 9] → 5
    Меняем 8 и 5: [1, 2, 5, 8, 9]
                          ↑ закреплено

Результат: [1, 2, 5, 8, 9]
```

**Сложность:** O(n²) - МЕДЛЕННАЯ
**Память:** O(1) - не требует дополнительной памяти

---

### 🔵 4. INSERTION SORT (Сортировка вставками)

**Идея:** "Как сортируют карты в руке"

Представь, что берешь карты по одной и вставляешь каждую на правильное место среди уже взятых карт.

**Визуализация:**
```
Исходный: [5, 2, 8, 1]

Шаг 1: [5] - первая карта уже "отсортирована"

Шаг 2: Берем 2, вставляем в [5]
    2 < 5 → вставляем перед: [2, 5]

Шаг 3: Берем 8, вставляем в [2, 5]
    8 > 5 → вставляем после: [2, 5, 8]

Шаг 4: Берем 1, вставляем в [2, 5, 8]
    1 < 2 → вставляем в начало: [1, 2, 5, 8]

Результат: [1, 2, 5, 8]
```

**Сложность:** O(n²) - МЕДЛЕННАЯ (но быстрая на почти отсортированных данных)
**Память:** O(1) - не требует дополнительной памяти

---

### 🔵 5. SHELL SORT (Сортировка Шелла)

**Идея:** "Улучшенная сортировка вставками"

Сортируем элементы, находящиеся на расстоянии `gap` (шаг). Затем уменьшаем `gap` и повторяем.

**Визуализация:**
```
Исходный: [5, 2, 8, 1, 9, 3, 7, 4]

Шаг 1: gap = 4 (сортируем элементы через 4 позиции)
    [5, 2, 8, 1, 9, 3, 7, 4]
     ↓        ↓              Сравниваем 5 и 9

    После gap=4: [5, 2, 7, 1, 9, 3, 8, 4]

Шаг 2: gap = 2
    После gap=2: [5, 1, 7, 2, 8, 3, 9, 4]

Шаг 3: gap = 1 (обычная сортировка вставками)
    После gap=1: [1, 2, 3, 4, 5, 7, 8, 9]
```

**Почему быстрее Insertion Sort?** Сначала большие "прыжки" быстро приближают элементы к правильным местам.

**Сложность:** O(n^1.5) - СРЕДНЯЯ
**Память:** O(1) - не требует дополнительной памяти

---

### 🔵 6. QUICK SORT (Быстрая сортировка)

**Идея:** "Разделяй по опорному элементу"

1. Выбрать опорный элемент (pivot)
2. Разделить: меньшие pivot влево, большие вправо
3. Рекурсивно отсортировать левую и правую части

**Визуализация:**
```
Исходный: [5, 2, 8, 1, 9, 3]

Шаг 1: Выбираем pivot = 3 (последний элемент)

Шаг 2: Разделяем
    Меньше 3: [2, 1]
    Pivot: [3]
    Больше 3: [5, 8, 9]

Шаг 3: Рекурсивно сортируем [2, 1] и [5, 8, 9]
    [1, 2] + [3] + [5, 8, 9]

Результат: [1, 2, 3, 5, 8, 9]
```

**Сложность:** O(n log n) в среднем, O(n²) в худшем случае - БЫСТРАЯ
**Память:** O(log n) - рекурсия использует стек

---

### 🔵 7. HEAP SORT (Пирамидальная сортировка)

**Идея:** "Используем пирамиду (кучу)"

**Куча** - это дерево, где родитель всегда больше детей.

**Визуализация кучи:**
```
        9
       / \
      8   7
     / \ / \
    5  2 3  1

В виде массива: [9, 8, 7, 5, 2, 3, 1]
```

**Алгоритм:**
1. Построить кучу из массива
2. Извлечь максимум (корень кучи) и поставить в конец
3. Восстановить кучу
4. Повторять до конца

**Визуализация:**
```
Исходный: [5, 2, 8, 1, 9]

Шаг 1: Построить кучу
        9
       / \
      5   8
     / \
    1   2

    Массив: [9, 5, 8, 1, 2]

Шаг 2: Извлечь 9, поставить в конец
    [2, 5, 8, 1 | 9]  ← 9 закреплен

Шаг 3: Восстановить кучу из [2, 5, 8, 1]
        8
       / \
      5   2
     /
    1

    Массив: [8, 5, 2, 1 | 9]

Продолжать...

Результат: [1, 2, 5, 8, 9]
```

**Сложность:** O(n log n) - БЫСТРАЯ
**Память:** O(1) - не требует дополнительной памяти

## 📈 СРАВНЕНИЕ СОРТИРОВОК ПО ОПЕРАЦИЯМ

### Теоретическая сложность (Big-O нотация)

| Сортировка | Лучший случай | Средний случай | Худший случай | Память |
|------------|---------------|----------------|---------------|---------|
| **Merge Sort** | O(n log n) | O(n log n) | O(n log n) | O(n) |
| **Bubble Sort** | O(n) | O(n²) | O(n²) | O(1) |
| **Selection Sort** | O(n²) | O(n²) | O(n²) | O(1) |
| **Insertion Sort** | O(n) | O(n²) | O(n²) | O(1) |
| **Shell Sort** | O(n log n) | O(n^1.5) | O(n²) | O(1) |
| **Quick Sort** | O(n log n) | O(n log n) | O(n²) | O(log n) |
| **Heap Sort** | O(n log n) | O(n log n) | O(n log n) | O(1) |

### Что означают эти обозначения?

- **O(n)** - линейная: удвоение размера массива удваивает время
- **O(n²)** - квадратичная: удвоение размера массива увеличивает время в 4 раза
- **O(n log n)** - логарифмическая: удвоение размера увеличивает время чуть больше чем вдвое

### Пример для массива из 100 элементов:

| Сортировка | Примерное кол-во операций |
|------------|---------------------------|
| Bubble Sort | ~10,000 (100²) |
| Selection Sort | ~10,000 (100²) |
| Insertion Sort | ~5,000 (зависит от данных) |
| Merge Sort | ~664 (100 × log₂100 ≈ 100 × 6.64) |
| Quick Sort | ~664 (в среднем) |
| Heap Sort | ~664 |
| Shell Sort | ~1,000-2,000 |

### Вывод:

✅ **Самые быстрые:** Merge Sort, Quick Sort, Heap Sort
⚠️ **Средние:** Shell Sort
❌ **Самые медленные:** Bubble Sort, Selection Sort, Insertion Sort

**НО!** Медленные сортировки имеют преимущества:
- Простые в реализации
- Не требуют дополнительной памяти
- Insertion Sort очень быстрая на почти отсортированных данных

# ЧАСТЬ 2: ГРАФЫ

## 🤔 ЧТО ТАКОЕ ГРАФ?

**Граф** - это математическая структура, состоящая из:
- **Вершин** (узлов) - точки
- **Рёбер** (связей) - линии между точками

### Пример из жизни: Карта городов

```
     Москва
      /  \
   300/    \500
    /        \
Питер ----200---- Казань
    \              /
   400\          /350
        \      /
         Сочи
```

**Вершины:** Москва, Питер, Казань, Сочи
**Рёбра:** Дороги между городами
**Веса рёбер:** Расстояния в километрах (300, 500, 200, и т.д.)

---

## 📊 МАТРИЦА СМЕЖНОСТИ

**Матрица смежности** - это таблица, где показано, какие вершины связаны и с каким весом.

### Пример: Граф из 4 городов

```
Граф:
    0 ---6---> 1
    |          |
    7          5
    |          ↓
    ↓          2
    3 ---3--->
```

**Матрица смежности:**
```
     0  1  2  3
  0 [0  6  0  7]
  1 [0  0  5  0]
  2 [0  0  0  3]
  3 [0  0  0  0]
```

**Как читать:**
- `[0][1] = 6` → из вершины 0 в вершину 1 ребро весом 6
- `[0][2] = 0` → нет ребра из 0 в 2
- `[2][3] = 3` → из вершины 2 в вершину 3 ребро весом 3

---

## ⚠️ ЧТО ТАКОЕ ОТРИЦАТЕЛЬНЫЕ ВЕСА?

### Откуда берутся отрицательные веса?

**Отрицательный вес** - это когда переход по ребру **уменьшает** общую "стоимость" пути.

### Примеры из жизни:

#### 1. **Финансы**
```
Банк A ---(+100 руб налог)---> Банк B
Банк B ---(-50 руб кешбэк)---> Банк C
```
Перевод из B в C даёт тебе кешбэк → отрицательная "стоимость"

#### 2. **Игры**
```
Комната A ---(теряешь 10 HP)---> Комната B
Комната B ---(восстанавливаешь 30 HP)---> Комната C
```
Восстановление HP → отрицательная "стоимость"

#### 3. **Логистика**
```
Склад A ---(+100 км)---> Склад B
Склад B ---(-20 км попутная доставка)---> Склад C
```
Попутная доставка сокращает расстояние → отрицательный вес

### В нашей программе:

```
Граф из input_graph.txt:
     0  1  2  3  4
  0 [0  6  0  7  0]
  1 [0  0  5  8 -4]  ← ребро 1→4 имеет вес -4
  2 [0 -2  0  0  0]  ← ребро 2→1 имеет вес -2
  3 [0  0 -3  0  9]  ← ребро 3→2 имеет вес -3
  4 [2  0  7  0  0]
```

**Отрицательные рёбра:**
- Из вершины 1 в 4: вес -4
- Из вершины 2 в 1: вес -2
- Из вершины 3 в 2: вес -3

---

## 🎯 ЗАДАЧА ПОИСКА КРАТЧАЙШИХ ПУТЕЙ

**Цель:** Найти кратчайший путь от **стартовой вершины** до **всех остальных** вершин.

### Пример:

```
Граф:
    A ---5---> B
    |          |
    2          1
    ↓          ↓
    C ---3---> D

Стартовая вершина: A
```

**Вопрос:** Какие самые короткие пути из A до B, C, D?

**Ответ:**
- A → A: 0 (сам себя)
- A → B: 5 (прямой путь A→B)
- A → C: 2 (прямой путь A→C)
- A → D: 5 (путь A→C→D = 2+3 = 5)

**Обрати внимание:**
Путь A→B→D (5+1=6) **длиннее**, чем A→C→D (2+3=5)!

# ЧАСТЬ 3: АЛГОРИТМ БЕЛЛМАНА-ФОРДА

## 🧠 КАК РАБОТАЕТ АЛГОРИТМ?

**Идея:** "Релаксация" рёбер много раз.

### Что такое "релаксация"?

**Релаксация ребра (u → v)** - это попытка улучшить путь к вершине v через вершину u.

```c
if (dist[u] + вес(u→v) < dist[v]) {
    dist[v] = dist[u] + вес(u→v);  // Нашли более короткий путь!
}
```

### Алгоритм Беллмана-Форда пошагово:

#### Шаг 0: Инициализация
```
dist[start] = 0
dist[все остальные] = ∞ (бесконечность)
```

#### Шаг 1-N: Релаксация всех рёбер (V-1 раз)
```
Для i от 1 до V-1:
    Для каждого ребра (u → v) с весом w:
        Релаксировать: dist[v] = min(dist[v], dist[u] + w)
```

#### Шаг N+1: Проверка отрицательных циклов
```
Для каждого ребра (u → v) с весом w:
    Если dist[u] + w < dist[v]:
        ЕСТЬ ОТРИЦАТЕЛЬНЫЙ ЦИКЛ!
```

---

## 📝 ПРИМЕР РАБОТЫ (ШАГ ЗА ШАГОМ)

### Граф:
```
    0 ---6---> 1
    |          |
    7          5
    ↓          ↓
    3 <--3---- 2
```

**Матрица:**
```
     0  1  2  3
  0 [0  6  0  7]
  1 [0  0  5  0]
  2 [0  0  0  3]
  3 [0  0  0  0]
```

**Стартовая вершина:** 0

### Инициализация:
```
dist[0] = 0
dist[1] = ∞
dist[2] = ∞
dist[3] = ∞
```

### Итерация 1: Релаксация всех рёбер

**Ребро 0→1 (вес 6):**
```
dist[0] + 6 = 0 + 6 = 6 < ∞
dist[1] = 6  ✓ Обновлено!
```

**Ребро 0→3 (вес 7):**
```
dist[0] + 7 = 0 + 7 = 7 < ∞
dist[3] = 7  ✓ Обновлено!
```

**Ребро 1→2 (вес 5):**
```
dist[1] + 5 = 6 + 5 = 11 < ∞
dist[2] = 11  ✓ Обновлено!
```

**Ребро 2→3 (вес 3):**
```
dist[2] + 3 = 11 + 3 = 14 > 7
Не обновляем (уже есть лучший путь)
```

**После итерации 1:**
```
dist[0] = 0
dist[1] = 6
dist[2] = 11
dist[3] = 7
```

### Итерация 2: Релаксация всех рёбер снова

(Продолжаем проверять все рёбра...)

**После итерации 2:**
```
dist[0] = 0
dist[1] = 6
dist[2] = 11
dist[3] = 7
```

Ничего не изменилось → **алгоритм завершён!**

## 🔢 КОЛИЧЕСТВО ОПЕРАЦИЙ (БЕЛЛМАН-ФОРД)

### Формула:
```
Количество операций = (V-1) × E × 3
```

Где:
- **V** - количество вершин
- **E** - количество рёбер
- **3** - примерное количество операций на релаксацию одного ребра

### Для нашего графа (5 вершин):

**Подсчёт рёбер (из матрицы смежности):**
```
0→1 (6), 0→3 (7)
1→2 (5), 1→3 (8), 1→4 (-4)
2→1 (-2)
3→2 (-3), 3→4 (9)
4→0 (2), 4→2 (7)

Всего рёбер: E = 10
```

**Расчёт:**
```
Операций = (5-1) × 10 × 3 = 4 × 10 × 3 = 120 операций
```

### Асимптотическая сложность:
```
O(V × E)
```

В худшем случае (полный граф): E = V²
Тогда: **O(V³)** - ОЧЕНЬ МЕДЛЕННО для больших графов!

# ЧАСТЬ 4: АЛГОРИТМ ДЕЙКСТРЫ

## 🧠 КАК РАБОТАЕТ АЛГОРИТМ?

**Идея:** "Жадный" выбор - всегда обрабатываем ближайшую непосещённую вершину.

### Алгоритм Дейкстры пошагово:

#### Шаг 0: Инициализация
```
dist[start] = 0
dist[все остальные] = ∞
visited[все] = false (не посещены)
```

#### Шаг 1-N: Основной цикл (V раз)
```
Для i от 1 до V:
    1. Найти непосещённую вершину u с минимальным dist[u]
    2. Пометить u как посещённую
    3. Для каждого соседа v вершины u:
        Релаксировать: dist[v] = min(dist[v], dist[u] + вес(u→v))
```

---

## 📝 ПРИМЕР РАБОТЫ (ШАГ ЗА ШАГОМ)

### Граф (БЕЗ отрицательных весов!):
```
    0 ---6---> 1
    |          |
    7          5
    ↓          ↓
    3 <--3---- 2
```

**Стартовая вершина:** 0

### Инициализация:
```
dist[0] = 0,   visited[0] = false
dist[1] = ∞,   visited[1] = false
dist[2] = ∞,   visited[2] = false
dist[3] = ∞,   visited[3] = false
```

### Итерация 1:

**Шаг 1.1:** Выбираем вершину с min dist и !visited
```
Кандидаты: 0(0), 1(∞), 2(∞), 3(∞)
Выбираем: u = 0 (dist=0)
```

**Шаг 1.2:** Помечаем 0 как посещённую
```
visited[0] = true
```

**Шаг 1.3:** Релаксируем соседей 0
```
Сосед 1: dist[1] = min(∞, 0+6) = 6  ✓
Сосед 3: dist[3] = min(∞, 0+7) = 7  ✓
```

**Состояние после итерации 1:**
```
dist:    [0, 6, ∞, 7]
visited: [T, F, F, F]
```

### Итерация 2:

**Шаг 2.1:** Выбираем вершину с min dist и !visited
```
Кандидаты: 1(6), 2(∞), 3(7)
Выбираем: u = 1 (dist=6)
```

**Шаг 2.2:** Помечаем 1 как посещённую
```
visited[1] = true
```

**Шаг 2.3:** Релаксируем соседей 1
```
Сосед 2: dist[2] = min(∞, 6+5) = 11  ✓
```

**Состояние после итерации 2:**
```
dist:    [0, 6, 11, 7]
visited: [T, T, F, F]
```

### Итерация 3:

**Выбираем:** u = 3 (dist=7)
```
visited[3] = true
(нет рёбер из 3 в нашем упрощённом примере)
```

### Итерация 4:

**Выбираем:** u = 2 (dist=11)
```
visited[2] = true
Релаксируем сосед 3: dist[3] = min(7, 11+3) = 7 (не изменилось)
```

**РЕЗУЛЬТАТ:**
```
dist[0] = 0
dist[1] = 6
dist[2] = 11
dist[3] = 7
```

## 🔢 КОЛИЧЕСТВО ОПЕРАЦИЙ (ДЕЙКСТРА С ПОЛНЫМ ПЕРЕБОРОМ)

### Формула:
```
Количество операций = V × (V + E)
```

Где:
- **V** операций на поиск минимума среди V вершин (на каждой итерации)
- **E** операций на релаксацию всех рёбер

### Для нашего графа (5 вершин, 10 рёбер):

**Подробный расчёт:**

**Итерация 1:**
- Поиск минимума среди 5 вершин: 5 сравнений
- Релаксация рёбер из вершины 0: 2 ребра × 3 операции = 6 операций
- Итого: 5 + 6 = 11 операций

**Итерация 2:**
- Поиск минимума среди 4 непосещённых: 4 сравнения
- Релаксация рёбер: ~6 операций
- Итого: 4 + 6 = 10 операций

**Итерация 3:**
- Поиск: 3 сравнения
- Релаксация: ~6 операций
- Итого: 9 операций

**Итерация 4:**
- Поиск: 2 сравнения
- Релаксация: ~6 операций
- Итого: 8 операций

**Итерация 5:**
- Поиск: 1 сравнение
- Релаксация: ~6 операций
- Итого: 7 операций

**ВСЕГО:**
```
11 + 10 + 9 + 8 + 7 = 45 операций
```

### Асимптотическая сложность:
```
O(V²)
```

Для полного графа (когда E ≈ V²): **O(V²)**

# ЧАСТЬ 5: СРАВНЕНИЕ АЛГОРИТМОВ ПО ОПЕРАЦИЯМ

## 🔥 БЕЛЛМАН-ФОРД vs ДЕЙКСТРА

### Таблица сравнения:

| Параметр | Беллман-Форд | Дейкстра (полный перебор) |
|----------|--------------|---------------------------|
| **Сложность** | O(V × E) | O(V²) |
| **Работает с отрицательными весами** | ✅ ДА | ❌ НЕТ |
| **Обнаруживает отрицательные циклы** | ✅ ДА | ❌ НЕТ |
| **Скорость на разреженных графах** | Медленнее | Быстрее |
| **Скорость на плотных графах** | Сравнимо | Сравнимо |

### Практический расчёт для графа 5 вершин, 10 рёбер:

**Беллман-Форд:**
```
Операций = (V-1) × E × 3
         = (5-1) × 10 × 3
         = 4 × 10 × 3
         = 120 операций
```

**Дейкстра:**
```
Операций ≈ V² + E × 3
         ≈ 5² + 10 × 3
         ≈ 25 + 30
         ≈ 55 операций
```

**Вывод:** На этом графе Дейкстра **в 2 раза быстрее**!

### Граф 100 вершин, 500 рёбер:

**Беллман-Форд:**
```
Операций = (100-1) × 500 × 3 = 148,500 операций
```

**Дейкстра:**
```
Операций ≈ 100² + 500 × 3 = 10,000 + 1,500 = 11,500 операций
```

**Разница:** Дейкстра **в 13 раз быстрее**!


**Дейкстра:**
```

```

## 🎯 КОГДА ИСПОЛЬЗОВАТЬ КАКОЙ АЛГОРИТМ?

### ✅ Используй БЕЛЛМАН-ФОРД, если:
- Граф содержит **отрицательные веса**
- Нужно обнаружить **отрицательные циклы**
- Граф **разреженный** (мало рёбер)
- Простота реализации важнее скорости

### ✅ Используй ДЕЙКСТРУ, если:
- Все веса **неотрицательные** (≥ 0)
- Нужна **максимальная скорость**
- Граф **плотный** (много рёбер)

### Примеры применения:

| Задача | Алгоритм | Почему? |
|--------|----------|---------|
| GPS навигация | Дейкстра | Расстояния всегда > 0 |
| Финансовые транзакции | Беллман-Форд | Могут быть кешбэки (отрицательные) |
| Маршруты авиабилетов | Дейкстра | Цены всегда > 0 |
| Игровая экономика | Беллман-Форд | Могут быть бонусы/скидки |
| Интернет-маршрутизация | Дейкстра | Задержки всегда > 0 |

## ⚠️ ПОЧЕМУ ДЕЙКСТРА НЕ РАБОТАЕТ С ОТРИЦАТЕЛЬНЫМИ ВЕСАМИ?

### Пример ошибки:

```
Граф:
    A ---5---> B
    |          |
    1         -10
    ↓          ↓
    C -------> D

Стартовая вершина: A
```

**Правильный ответ (Беллман-Форд):**
```
A → A: 0
A → B: 5
A → C: 1
A → D: -5  (путь A→B→D = 5+(-10) = -5)
```

**Неправильный ответ (Дейкстра):**
```
A → A: 0
A → B: 5
A → C: 1
A → D: 1  (путь A→C→D, не заметил более короткий A→B→D)
```

**Почему ошибка?**

Дейкстра:
1. Сначала обработал C (dist=1), пометил как посещённый
2. Потом обработал B (dist=5)
3. НЕ СМОГ вернуться к C, чтобы улучшить путь через B→D→C

**Вывод:** Дейкстра "жадный" - помечает вершину как посещённую и не возвращается к ней. Это не работает с отрицательными весами!

```c
    // Сначала сравниваем по имени
    int name_cmp = strcmp(p1->name, p2->name);

    // Если имена равны, сравниваем по возрасту

    return 0;
```

```c
static void swap_elements(void* a, void* b, size_t size) {

    memcpy(temp, a, size);  // temp = a
    memcpy(a, b, size);     // a = b
    memcpy(b, temp, size);  // b = temp

    free(temp);
}
```

#### 1. `bellman_ford()` - Алгоритм Беллмана-Форда
```c
void bellman_ford(int** graph, int vertices, int start_vertex, int* distances) {
    // Инициализация
    for (int i = 0; i < vertices; i++) {
        distances[i] = INF;
    }
    distances[start_vertex] = 0;

    // Релаксация рёбер V-1 раз
    for (int i = 0; i < vertices - 1; i++) {
        for (int u = 0; u < vertices; u++) {
            if (distances[u] == INF) continue;

            for (int v = 0; v < vertices; v++) {
                if (graph[u][v] != 0) {
                    long long new_dist = (long long)distances[u] + graph[u][v];

                    if (new_dist < distances[v]) {
                        distances[v] = (int)new_dist;
                    }
                }
            }
        }
    }
}
```

**Важные детали:**
- `distances[u] == INF` → пропускаем недостижимые вершины
- `graph[u][v] != 0` → проверяем наличие ребра (0 = нет ребра)
- `long long new_dist` → защита от переполнения при сложении

#### 2. `dijkstra()` - Алгоритм Дейкстры
```c
void dijkstra(int** graph, int vertices, int start_vertex, int* distances) {
    int* visited = (int*)malloc(vertices * sizeof(int));

    // Инициализация
    for (int i = 0; i < vertices; i++) {
        distances[i] = INF;
        visited[i] = 0;  // false
    }
    distances[start_vertex] = 0;

    // Главный цикл
    for (int count = 0; count < vertices; count++) {
        // Поиск минимума (ПОЛНЫЙ ПЕРЕБОР)
        int min_vertex = -1;
        int min_distance = INF;

        for (int v = 0; v < vertices; v++) {
            if (!visited[v] && distances[v] < min_distance) {
                min_distance = distances[v];
                min_vertex = v;
            }
        }

        if (min_vertex == -1) break;  // Нет доступных вершин

        visited[min_vertex] = 1;  // Помечаем как посещённую

        // Релаксация соседей
        for (int v = 0; v < vertices; v++) {
            if (graph[min_vertex][v] != 0 && !visited[v]) {
                long long new_dist = (long long)distances[min_vertex] + graph[min_vertex][v];

                if (distances[min_vertex] != INF && new_dist < distances[v]) {
                    distances[v] = (int)new_dist;
                }
            }
        }
    }

    free(visited);
}
```

**Важные детали:**
- `visited[]` → массив для отслеживания посещённых вершин
- Полный перебор для поиска минимума → O(V²)
- `if (min_vertex == -1)` → все оставшиеся вершины недостижимы

### **output_dijkstra.txt** (Дейкстра)
```
=== REZULTATY ALGORITMA BELLMANA-FORDA ===
Kratchajshie puti iz vershiny 0:

Vershina 0: 0
Vershina 1: 6
Vershina 2: 4
```

**Обрати внимание:** Результаты Беллмана-Форда и Дейкстры **разные** из-за отрицательных весов!

# ЧАСТЬ 7: FAQ - ЧАСТЫЕ ВОПРОСЫ

## ❓ ОБЩИЕ ВОПРОСЫ

### 1. Почему результаты Беллмана-Форда и Дейкстры разные?

**Ответ:**
Потому что граф содержит **отрицательные веса**!

- **Беллман-Форд:** Работает правильно с отрицательными весами → **правильный результат**
- **Дейкстра:** НЕ работает с отрицательными весами → **неправильный результат**

**Пример:**
```
Беллман-Форд: Вершина 4: -2  ← Правильно!
Дейкстра:     Вершина 4: 2   ← Неправильно!
```

---

### 2. Что такое "универсальная" сортировка?

**Ответ:**
Это функция, которая может сортировать **любой тип данных**, используя:
- `void*` - универсальный указатель
- `size_t` - размер элемента
- Функцию сравнения

**Пример использования:**
```c
// Сортировка int
universal_bubble_sort(int_array, count, sizeof(int), compare_int);

// Сортировка Person
universal_bubble_sort(person_array, count, sizeof(Person), compare_person);

// Можно сортировать даже double, float, и любые другие типы!
```

---

### 3. Зачем нужно 7 разных сортировок?

**Ответ:**
Каждая сортировка имеет свои **преимущества и недостатки**:

- **Bubble, Selection, Insertion** - простые, медленные, но не требуют памяти
- **Merge, Quick, Heap** - быстрые, сложнее реализация
- **Shell** - компромисс между простотой и скоростью

**В реальной жизни:**
- **Маленькие массивы (<50 элементов):** Insertion Sort
- **Средние массивы:** Quick Sort
- **Большие массивы:** Merge Sort или Heap Sort
- **Почти отсортированные:** Insertion Sort

---

### 4. Что такое Big-O нотация?

**Ответ:**
Это способ описания **скорости роста** времени выполнения алгоритма при увеличении размера данных.

**Примеры:**

| Обозначение | Название | Пример | Рост времени |
|-------------|----------|--------|--------------|
| O(1) | Константная | Доступ к элементу массива | Не растёт |
| O(log n) | Логарифмическая | Бинарный поиск | Медленно растёт |
| O(n) | Линейная | Обход массива | Удвоение n → удвоение времени |
| O(n log n) | Логлинейная | Merge Sort | Чуть быстрее, чем n² |
| O(n²) | Квадратичная | Bubble Sort | Удвоение n → время ×4 |
| O(2ⁿ) | Экспоненциальная | Перебор всех подмножеств | ОЧЕНЬ быстро растёт |

**Практический пример:**

Массив из 1000 элементов:
- O(n): ~1000 операций
- O(n log n): ~10,000 операций
- O(n²): ~1,000,000 операций

## ❓ ВОПРОСЫ ПРО ГРАФЫ

### 5. Что такое "путь" в графе?

**Ответ:**
**Путь** - это последовательность вершин, соединённых рёбрами.

**Пример:**
```
Граф:
    A → B → C
    ↓       ↑
    D ------+

Пути из A в C:
1. A → B → C (длина: вес(A→B) + вес(B→C))
2. A → D → C (длина: вес(A→D) + вес(D→C))
```

**Кратчайший путь** - путь с минимальной суммой весов.

---

### 6. Что такое "отрицательный цикл"?

**Ответ:**
**Отрицательный цикл** - это замкнутый путь, сумма весов которого **отрицательная**.

**Пример:**
```
    A ---(+5)---> B
    ↑             |
    |           (-10)
    |             ↓
    +----(-2)---- C

Цикл: A → B → C → A
Сумма: 5 + (-10) + (-2) = -7  ← Отрицательный!
```

**Проблема:**
Если есть отрицательный цикл, можно бесконечно уменьшать расстояние, проходя цикл снова и снова:
```
Путь A→B: 5
Путь A→B→C→A→B: 5 + (-7) = -2
Путь A→B→C→A→B→C→A→B: -2 + (-7) = -9
...и так до -∞
```

**Решение:**
Беллман-Форд обнаруживает такие циклы и сообщает об ошибке!

---

### 7. Почему в матрице смежности 0 = нет ребра?

**Ответ:**
Это **соглашение** в нашей реализации.

**Альтернатива:** Можно использовать `INF` (бесконечность) для обозначения отсутствия ребра, но 0 проще.

**Проблема:** Если есть ребро с весом 0, то 0 ≠ "нет ребра". В таком случае нужно использовать другое значение (например, -1 или INF).

**В нашей программе:**
```c
if (graph[u][v] != 0) {
    // Есть ребро из u в v
}
```

## ❓ ВОПРОСЫ ПРО C

### 8. Что такое void*?

**Ответ:**
`void*` - это **универсальный указатель**, который может указывать на данные **любого типа**.

**Аналогия:**
Представь коробку, которая может хранить что угодно: книгу, телефон, фрукт. Но чтобы достать, нужно знать, что внутри.

**Пример:**
```c
int x = 42;
void* ptr = &x;  // ptr указывает на int

// Чтобы использовать, нужно преобразовать обратно:
int value = *(int*)ptr;  // Преобразуем void* → int*
```

**Почему нельзя просто `*ptr`?**
Потому что компилятор не знает, сколько байт читать!
- `int` - 4 байта
- `Person` - 16 байт
- `double` - 8 байт

---

### 9. Что такое malloc и free?

**Ответ:**
- **`malloc(size)`** - выделяет `size` байт в **динамической памяти** (куче)
- **`free(ptr)`** - освобождает память, выделенную malloc

**Пример:**
```c
// Выделяем память для 10 чисел int
int* array = (int*)malloc(10 * sizeof(int));

// Используем массив
array[0] = 42;

// Обязательно освобождаем память!
free(array);
```

**Почему важно вызывать free?**
Иначе будет **утечка памяти** - программа будет занимать всё больше и больше памяти, пока не закончится!

---

### 10. Что такое memcpy?

**Ответ:**
`memcpy(dest, src, size)` - копирует `size` байт из `src` в `dest`.

**Пример:**
```c
int a = 42;
int b;

memcpy(&b, &a, sizeof(int));  // b = 42
```

**Зачем memcpy в универсальной сортировке?**
Потому что мы не знаем тип данных! memcpy копирует **байты**, не заботясь о типе.

```c
// Обмен двух элементов неизвестного типа:
char temp[size];
memcpy(temp, a, size);  // temp = *a
memcpy(a, b, size);     // *a = *b
memcpy(b, temp, size);  // *b = temp
```

## ❓ ВОПРОСЫ ПРО РЕЗУЛЬТАТЫ

### 11. Почему некоторые вершины "nedostizhima"?

**Ответ:**
Потому что **нет пути** от стартовой вершины до этой вершины.

**Пример:**
```
Граф:
    0 → 1 → 2

    3 → 4  ← Отдельный компонент!

Стартовая вершина: 0
```

**Результат:**
```
Вершина 0: 0
Вершина 1: (расстояние от 0 до 1)
Вершина 2: (расстояние от 0 до 2)
Вершина 3: nedostizhima  ← Нет пути из 0!
Вершина 4: nedostizhima  ← Нет пути из 0!
```

### 12. Почему алгоритмы дают разные результаты на одном графе?

**Ответ:**
Только если граф содержит **отрицательные веса**!

- **Беллман-Форд:** Правильно работает с отрицательными весами
- **Дейкстра:** Даёт неправильный результат при отрицательных весах

**На графе БЕЗ отрицательных весов:** Оба алгоритма дадут **одинаковый** правильный результат!

**Проверка:**

## ❓ ВОПРОСЫ ПРО ОПТИМИЗАЦИЮ

### 14. Какую сортировку использовать для моей задачи?

| Ситуация | Рекомендация |
|----------|--------------|
| Маленький массив (<50) | Insertion Sort |
| Массив уже почти отсортирован | Insertion Sort |
| Нужна стабильная сортировка | Merge Sort |
| Мало памяти | Heap Sort или Quick Sort |
| Нужна максимальная скорость | Quick Sort (в среднем) |
| Гарантированная O(n log n) | Merge Sort или Heap Sort |

**Стабильная сортировка** - сохраняет порядок равных элементов.

---

### 15. Как ускорить Дейкстру?

**Ответ:**
Использовать **приоритетную очередь** (heap) вместо полного перебора!

**Сложность:**
- Полный перебор: O(V²)
- С приоритетной очередью: O((V + E) log V)

**Для плотных графов (E ≈ V²):** Разница небольшая
**Для разреженных графов (E ≈ V):** Ускорение в **V** раз!
